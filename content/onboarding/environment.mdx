# Dev Environment Setup

**Budget about 45 minutes**, most of it waiting on installs. Start with the
handbook — it is the smallest clone and it proves your toolchain before
anything harder depends on it.

## Prerequisites

<Checklist id="env-prereqs">
  <Task>**Node.js 22** through a version manager (`fnm` or `nvm`), not a system package. The platform requires ≥ 20 and its CI runs 22 — `jumeira` and `aladawy-pack` run 24, so check the repo's workflow rather than assuming one version.</Task>
  <Task>**pnpm** — `corepack enable` is the simplest route. Every repo except this handbook uses it.</Task>
  <Task>**Git**, configured with your name and work email.</Task>
  <Task>**An SSH key on your GitHub account.** Every clone command here is `git@github.com:…`, so without one the very first command fails with `Permission denied (publickey)`. [GitHub's guide](https://docs.github.com/en/authentication/connecting-to-github-with-ssh) — generate, then add to your account, then `ssh -T git@github.com` to confirm.</Task>
  <Task>**The Vercel CLI** (`npm i -g vercel`), then `vercel login`. Needed for `vercel env pull` and for the one repo that deploys by hand.</Task>
  <Task>**An editor** with TypeScript, ESLint and Prettier integration.</Task>
  <Task>**Python 3** — only if you will touch `baron-menu`, `jumeira` or `zad-alhkoul`, whose asset scripts need it.</Task>
  <Task>**ffmpeg and a bash shell** — only for [`jumeira`](/repositories/jumeira)'s audio and film bakes. Neither is needed to build or run it: every bake's output is committed, so a fresh clone needs none of this.</Task>
</Checklist>

<Callout type="info">
  Ticks are saved in your own browser and go no further. This is a bookmark so
  you can come back to a half-finished setup, not a record anyone reads — the
  [board](/how-we-work/the-board) is where work is tracked.
</Callout>

## Start here: the handbook

```bash
git clone git@github.com:Adawy-Group/adawy-technical-docs.git
cd adawy-technical-docs
npm install
npm run dev              # → http://localhost:3000

node scripts/check-links.mjs   # both of these must pass before any PR
npm run build
```

If those two pass, your toolchain is correct.

<Callout type="important">
  **`node scripts/check-links.mjs` is a separate CI gate and it runs first.**
  It catches the two mistakes a first documentation PR is most likely to make:
  a mistyped or relative cross-section link, and a new page missing from its
  folder's `_meta.ts`. `npm run build` will not catch either.
</Callout>

## The platform monorepo

Install once at the root, then run a single app. Everything runs from the repo
root; `--filter` scopes a task to one workspace.

```bash
git clone git@github.com:Adawy-Group/adawy-platform.git
cd adawy-platform

pnpm install                       # installs all apps and @adawy/* packages
pnpm turbo dev --filter=group      # → http://localhost:3000, redirects to /en

# what CI gates on — run both lines before pushing
pnpm turbo lint typecheck test build
pnpm format:check
```

Workspace names: `group`, `studio`, `pack`, `@adawy/ui`, `@adawy/design`,
`@adawy/motion`, `@adawy/i18n`, `@adawy/site`, `@adawy/holding`,
`@adawy/eslint-config`, `@adawy/typescript-config`.

A single test runs from inside the app:

```bash
pnpm --filter=group exec vitest run lib/ease.test.ts
pnpm --filter=group exec vitest                       # watch mode
```

## Client projects

The Next.js client repos follow the same shape — no workspace, no filters:

```bash
pnpm install
pnpm dev
pnpm lint typecheck test
pnpm format:check
```

Two run something different, and running the wrong one means a red CI on a
green local:

- **`zad-alhkoul`** has no `test` script. Its whole gate is one composed
  command: **`pnpm verify`** (typecheck → lint → format:check → check:i18n →
  build).
- **`baron-menu`** needs no install at all — serve the folder:

  ```bash
  python3 -m http.server 8848   # → http://localhost:8848
  ```

  On Windows that is `python -m http.server 8848`.

## Environment variables

Never copied from chat, never committed, never invented.

```bash
vercel login                  # once
vercel link                   # once per repo, inside the repo
vercel env pull .env.local    # for Vercel-linked projects
```

Only two repos document their variables in a committed `.env.example`
(`adawy-platform`, in `apps/group/`, and `zad-alhkoul`). The rest boot with
none. Anything not covered comes from the team password manager or the CTO —
**never invent a value** ([security](/standards/security)).

What each prefix means, and why it is a security fact rather than a naming
one: [Next.js & React](/standards/nextjs#environment-variables-and-configuration).

## Common issues

| Symptom | Cause → fix |
| ------- | ----------- |
| `Permission denied (publickey)` on the first clone | No SSH key on your GitHub account. Generate one, add it, then `ssh -T git@github.com` |
| `pnpm: command not found` after `corepack enable` | Corepack is enabled but pnpm has not been provisioned — run `corepack prepare pnpm@latest --activate`, or install pnpm directly |
| Dependency errors that make no sense in a platform or client repo | You ran `npm install` in a pnpm repo. Delete `node_modules` and `package-lock.json`, then `pnpm install` |
| Wrong Node version errors | You skipped the version manager — `fnm use 22` / `nvm use 22`. Only some repos pin a version, so name it explicitly |
| `Error: Your codebase isn't linked to a project` from `vercel env pull` | Run `vercel link` in that repo first |
| CI fails on formatting after a green local `turbo lint` | `pnpm format:check` is a separate gate and is not a turbo task. Run it too |
| A class exists in your source but not in the served CSS | Stale Turbopack CSS chunk — `rm -rf .next` (or `apps/<app>/.next`) and restart. A plain restart is not enough |
| Build fails on a page that renders fine in dev | Prerender error — run the dev server and open that route; dev shows the real message the build hides |
| `Invalid input: expected nonoptional` (handbook repo) | The `zod` override drifted — keep the pin in `package.json` and `npm install` again |
| A shared-package change doesn't appear in the running app | Restart the filtered dev task; if it persists, `pnpm turbo build --force` the package |

<Callout type="info">
  Every command in this handbook is POSIX. On Windows, run them in **Git Bash
  or WSL** rather than PowerShell — `rm -rf`, a trailing `&` and `python3` all
  behave differently otherwise.
</Callout>

Anything not covered here belongs in [Troubleshooting](/help/troubleshooting) —
and adding it is a perfect first PR.
