## The two worlds

The department builds two kinds of software, and almost every rule here applies
to one of them rather than both:

| | **Group work** | **Client work** |
| --- | --- | --- |
| For | Adawy Group's own brands | Other businesses |
| Lives in | One monorepo, `adawy-platform` | One standalone repo per client |
| Shares | The `@adawy/*` packages | Standards only — never code |
| Today | `apps/group`, `apps/studio`, `apps/pack` | `aladawy-pack`, `aladawy-shop`, `jumeira`, `zad-alhkoul`, `baron-menu` |

[ADR-010](/architecture/adrs) records why, and
[Client Projects](/how-we-work/client-projects) covers how client work runs.
One repository sits in neither —
[the open case](/repositories#the-third-case-and-the-open-question).

## The one-paragraph context

> **Move As One.** Businesses grow better when everything works together.

Adawy Group is an integrated industrial and business ecosystem — 38 companies
today, planned to grow past 100 — connecting manufacturing, packaging,
branding, marketing, technology, and AI under one infrastructure. The software
department exists to build the **digital infrastructure** of that ecosystem:
first the websites (one monorepo platform powering every brand site), then
the client portal that makes ecosystem membership a daily product rather than
a marketing claim, then the employee portal that brings the same clarity to
the group's own teams. Alongside that roadmap, the department also **delivers
software for clients** — the same standards, separate repositories.

## How this handbook works

1. **Why before what.** Every rule and decision documents its business reason.
   A rule without a reason is a candidate for deletion — including the ones
   already here.
2. **Docs as code.** Everything lives in git, ships by pull request, and is
   gated by the same CI discipline as the products
   ([ADR-007](/architecture/adrs)).
3. **One fact, one home.** Mechanics that change when the code changes live
   *beside the code*, in each repo's `AGENTS.md` and `docs/`. This handbook
   holds the *why* and the *policy* — because a page here that duplicated a
   file path would go stale silently, since nothing here fails when a
   repository is refactored.
4. **If it's not written here, it's not the process.** Found tribal knowledge?
   Add it. That is a legitimate card, and for documentation it does not even
   need one.
