# Definition of Done

The department's quality standard has two gates — one before building starts,
one before work is called done. They keep one consistent standard across
everything we ship.

## Ready to build

Work enters **Ready for Dev** only when:

- ✅ Its design is **approved**
- ✅ It is **fully specified** — the card carries the Figma link, the
  checklist of what counts as done, a target date, and an owner

No building on guesses. If the spec is ambiguous, the card goes back to
Design, not forward to In Progress.

*Why a gate before the work rather than a conversation during it:* a question
answered mid-build is answered by whoever is at their desk, and the answer
lands in a chat nobody can find again. A card that goes back to Design costs a
day; a feature built against a guess costs the rebuild, plus the argument about
whose guess it was.

## Done

Work is **done** only when:

- ✅ **Automated checks passed** — lint, types, tests and build, plus the
  formatting and accessibility gates that are not part of them
  ([what each red check means](/onboarding/first-pr#when-a-check-goes-red))
- ✅ Code **reviewed and merged** via a PR linked to its card
- ✅ **Opened on the deployed URL by a human** — on a real phone if it is
  visual, and in Arabic as well as English if it touched layout
- ✅ **No regressions** — the [performance
  budget](/guides/performance-checklist#the-numbers-and-which-one-blocks-a-merge)
  held
- ✅ Documentation updated where the change affects it: this handbook, the
  repo's README or `AGENTS.md`, or an [ADR](/architecture/adrs) for a decision
  that closes off an alternative

"Done" never means "works on my machine," "merged but not deployed," or
"deployed but nobody checked." It means **live, verified, and closed** — the
card moves to Done and the next one is pulled.

*Why a human still has to open the page:* every automated gate proves the code
compiled, typed, linted and passed its own tests. None of them proves the thing
the card asked for is on the screen. The two failures this department has
already written down — a green deploy that built the wrong app, and a form that
returned success into nothing — were invisible to every check and obvious to
anyone who looked.
