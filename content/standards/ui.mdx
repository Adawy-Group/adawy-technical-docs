# UI & Brand Standards

Adawy Group's identity is **authentic, corporate, industrial, scalable,
structured** — institutional infrastructure, not a trendy creative brand.
Every interface we ship must hold that feeling. The full source of truth is
the brand guidelines document; this page is the engineering-facing distillation.

## Color

Primary palette: **black, white, industrial gray** — timeless, technical,
institutional.

| Color | Usage ratio |
| ----- | ----------- |
| Black | ~50% |
| White | ~35% |
| Gray | ~15% |

Avoid: bright/saturated palettes, neon tones, trend gradients, color-heavy
layouts. Sub-brands have their own accent identities — applied through design
tokens, never hard-coded.

## Typography

- **English:** Helvetica Now, Neue Haas Grotesk, General Sans, Satoshi
- **Arabic:** Cairo, IBM Plex Arabic, DIN Next Arabic

Style: bold headlines, large clean layouts, strong hierarchy, wide spacing,
structured alignment, minimal clutter.

## Layout & design character

Designs should feel like industrial annual reports and architectural
presentations: **grid-based, large negative space, structured composition,
technical alignment, clean hierarchy.** Avoid overdesigned layouts, random
graphic elements, visual clutter, excessive effects.

## The token layers

Every repo in the org themes through tokens rather than literals, and the ones
that do it well use the **same three layers, in this order**:

| Layer | What it holds | Who reads it |
| ----- | ------------- | ------------ |
| `@theme` | The raw design scales, exactly as the design file states them | Nothing in a component. Never edited per page |
| `:root` / `.dark` | The semantic contract — `background`, `foreground`, `primary`, `border`… | **This is the only layer components use** |
| `@theme inline` | Maps the contract into Tailwind's utility namespace | The utilities |

Use **shadcn/ui's own token names** in the semantic layer. Anything pulled from
the registry then inherits the brand with no edits, which is the whole point —
and it means `--secondary` is the brand accent while `--accent` is shadcn's
*hover surface*, not a brand accent. Reach for `--secondary` when you mean the
brand's colour.

**Put the theme class on `<html>`, never on a wrapper inside `<body>`.** The
root background is what paints the overscroll area, so a wrapper-scoped `.dark`
leaves a white band the moment the page is rubber-banded past its end. Set
`colorScheme` to match so the UA paints scrollbars and form controls dark too.

<Callout type="important">
  **The layering is worth a test, because none of these mistakes look like
  mistakes.** [`jumeira`](/repositories/jumeira) holds three rules in a
  stylesheet test: no colour literal outside the scale layer, **no colour
  literal inside `:root` or `.dark`** — the semantic layer is references only —
  and no cross-section `z-index` written as a number. All three were prose
  first, and writing the test found four live violations, including a gradient
  stop documented as the midpoint of two steps and typed out as the hex it
  happened to resolve to. Moving either step would have left it behind, and
  nothing would have failed ([pattern 6](/architecture/patterns)).
</Callout>

A stacking scale belongs in the tokens for the same reason. A section ordering
its own children can stay on bare `0`/`1`/`2` — each section is its own stacking
context, so those cannot reach out of it and naming them globally would say the
opposite. What must be named is the **cross-section deck**, which is otherwise
the same five numbers written out in five stylesheets.

## Motion

Cinematic and intentional — GSAP (the platform's single animation library)
with Lenis smooth scrolling, both wired once in `@adawy/motion` and imported
only from there. **Client repos reimplement that gateway rather than importing
it** — one module for GSAP and plugin registration, one for the scroll
instance, and a lint rule confining both ([client projects](/how-we-work/client-projects)).
The pattern transfers; the package does not. Controlled pacing, structured cuts, minimal transitions.
Never TikTok-style editing, meme transitions, or hyperactive motion.
**Always respect `prefers-reduced-motion`** — the shared primitives handle
this (Lenis falls back to native scroll; reveals render static), and custom
choreography must too. Motion is brand, accessibility is law.

## Imagery

Real, documentary, industrial: factories, production lines, machinery,
packaging processes, real meetings, execution environments. **Never obvious
stock photography** — the audit showed exactly how much credibility Unsplash
images cost a branding business. Until original photography exists, an honest
photo of the factory floor beats polished stock.

## Voice in the UI (microcopy)

Tone: **strategic confidence** — calm authority, clear, precise, human without
exaggeration.

- ✅ "Connected systems create scalable businesses." / "Build Smarter." /
  "From Idea To Expansion."
- ❌ "We are the best", "Think outside the box", "Hurry up", "DM us today",
  clickbait, hype, startup clichés.

## Accessibility & bilingual

- WCAG 2.1 AA on everything: contrast, focus states, keyboard navigation,
  meaningful alt text, no screen-reader traps (marquee duplicates get
  `aria-hidden`).
- Every layout must survive **RTL** and Arabic text lengths from day one —
  bilingual is designed in, not bolted on. Use logical Tailwind classes
  (`ms-`/`me-`/`ps-`/`pe-`/`start-`/`end-`/`text-start`/`text-end`); the
  physical ones are [lint errors](/standards/coding).

## Which primitive library

The org runs two, and the split is historical rather than principled:

| Library | Where | |
| ------- | ----- | --- |
| **Base UI** | `@adawy/ui` in the platform, `zad-alhkoul`, `adawy-group-links` | **Where new work starts** — it is what the shared package uses |
| Radix | `aladawy-pack`, `aladawy-shop`, `jumeira` (on the unified `radix-ui` package) | Fine where it is. Not a reason to migrate a working site |

*Why it matters to know:* the two have different APIs for the same shapes, so a
component copied between repos will not compile, and a fix found in one does
not transfer. Check the repo's `package.json` before you reach for a
primitive.

## Component rules

- Build with the shared design system: `@adawy/ui` (shadcn-based primitives +
  section components), themed by `@adawy/design` tokens, animated
  with `@adawy/motion`. Check whether a component exists before writing one.
- **A vendored shadcn component is ours to edit.** When a consumer needs
  different geometry, change the component — do not out-specify it from the
  call site. *Why:* shadcn's defaults are variant-scoped
  (`data-[size=default]:h-8`, `dark:bg-input/30`), and tailwind-merge does not
  treat a bare utility and a modified one as conflicting, so a plain `h-14`
  passed in `className` loses no matter where it sits in the list. One form in
  the platform once carried ~90 lines whose only job was to fight its own
  components.
- **A `dark:` rule can only be displaced by another `dark:` rule.** Keep fills
  theme-neutral in the primitive (`bg-transparent`) and let the tokens invert.
- **Never hard-code a brand colour or font in a shared package.** Brands
  restyle through token overrides in their own `globals.css` — that is the
  whole mechanism ([project structure](/standards/project-structure)).
- New reusable component → it goes in `@adawy/ui`, themeable via tokens,
  accessible, documented, reviewed as platform code (it will run on every
  brand app).
- Brand-specific need → first ask whether it's a token override; only flagship
  brands get genuinely custom components, explicitly scoped — and they live in
  that brand's app, never as edited copies of shared ones.
